# 训练数据质量审计报告（h2_remain 氢气剩余量）

> 日期：2026-08-22 · 项目：hydrogen-newline-predictor（T05 命题二）
> 触发：模型对"天津→乌兰察布"等线路预测氢耗低至 2~3 kg/100km，与官方满载锚点（7.1 kg/100km）偏离，
> 于是对训练数据的**目标变量来源（h2_remain）**做了全链路审计。
> 结论：**模型链路完整（特征/工况合成/训练/预测/校准），预测偏低源于企业原始数据 h2_remain 的质量问题**。

---

## 1. 审计方法：能量对账（金标准）

车上两个独立信号必须满足能量守恒：

- **电机电表**（三电机 V×I，官方换算：电流 offset −1000A、电压 ×0.1）→ 电机输出电能
- **氢气表**（h2_remain 下降）→ 氢气提供的能量（1kg ≈ 33.3 kWh）

$$\text{对账比} = \frac{E_{motor}}{E_{h2}} \quad \text{物理上应}<0.5 \ (\eta_{fc}\approx0.5,\ \eta_{mt}\approx0.9,\ \text{附件另占})$$

**电机功率换算已验证正确**：停车帧（v<1）电机功率精确为 0；高速巡航 75~85km/h 电机功率 68~82kW，与 20~40t 载重理论值（63~107kW）吻合。

## 2. 审计结果

### 2.1 原始 h2_remain 毛刺占比 >99.9%（问题源头）

| 车辆1 原始数据 | 数值 |
| --- | --- |
| h2_remain "总下降"（逐帧差分，上限 2kg/帧） | **73,686 kg** |
| 可靠信号（清洗后 per_sec 总和） | 65 kg |
| 储氢量（H49） | 50~80 kg |
| 毛刺/真实信号比 | **≈800 倍** |

→ **h2_remain 整列几乎全是虚假毛刺**，不是个别异常。

### 2.2 清洗后目标仍系统性低估约 2 倍

用户清洗算法（0 值替换 → 60 帧窗口波动>2kg 磨平 → 拉回基线保证单调递减）逻辑合理，
清洗后 `h2_consum_per_sec` 与 `h2_remain` 差分自洽（65kg vs 70kg）。但：

| 车辆 | 清洗后 h2 总消耗 | 电机能量反推理论氢耗（÷0.5÷0.9） | 低估 |
| --- | --- | --- | --- |
| 车辆1 | 65 kg | ≈130 kg | ~2× |
| 车辆2 | 348 kg | ≈700 kg | ~2× |

→ 在毛刺 800 倍于信号的背景下，清洗的"磨平/拉回"会连带抹掉窗口/区间内的真实消耗，
任何算法都难以完全恢复。**这是数据的固有限制，不是模型或清洗方法的问题。**

### 2.3 累计氢耗列（备选信号）同样不可靠

- `celDataExt_h2_total_consume_累计氢耗` 单调递增（零负增量），但存在**大量清零重置**
  （总增量 10838kg vs 首末差 93kg），且与 h2_remain **同源**（差分一致），不能独立校准。
- 原始数据时间戳存在重复/错乱，按时间差切分的行程里程出现上万公里异常值。

## 3. 对模型预测的影响

- 训练目标（段 h2_per_km）被低值行程系统性拉低 → 模型对高速/高海拔段预测偏低（2~4 kg/100km）
- 官方满载锚点 7.1 kg/100km 是**专项满载定速验证**（青岛—天津/武汉—宜昌），与这批"日常运营
  数据"（含空载高原 2.5 kg/100km，物理真实）口径不同，不可直接对比

## 4. 结论与建议（给企业 / 评审的说明）

1. **我方完成的工作**：完整数据链路（原始 CSV → 回填 DEM/ERA5/道路等级 → 清洗聚合 → 5km 段 →
   工况合成 → HistGB 训练 → 预测/校准/前端载重曲线），并做了能量对账级别的数据质量审计。
2. **预测与官方 7.1 的偏离**：源于企业原始数据 h2_remain 的毛刺（>99.9%）与系统性低估（~2×），
   模型忠实学习了这批标签，非模型缺陷。
3. **建议企业提供**：可靠的气瓶压力/储氢量计量（或按加氢记录校准的 h2_remain），
   或累计氢耗的原始计数值（无重置），即可显著提升目标精度。
4. **后续可用**：本报告的"能量对账"方法可复用到任何新数据的质量校验。
