1为什么要有物理模型？

我们已经有了一台效果不错的数据模型（HistGB 机器学习）。为什么还要再"手搓"一台物理模型？因为它们的性格刚好互补：

对比项数据模型（HistGB，已有）物理模型（本设计）
靠什么算两辆实车的历史数据 + 特征工程能量守恒 + 车辆动力学公式
换车能行吗换一辆没学过的车，基本抓瞎改几个参数（重量/风阻/电堆功率）就能适配新车型
换载重能行吗训练数据里载重覆盖有限，外推不稳质量 m 直接进公式，空载/满载天然可算
能解释吗黑箱，只能看特征重要度每一步都有物理意义，答辩能讲清楚
短板数据覆盖不到的场景会偏对"没写进公式的细节"（驾驶风格等）不敏感
定位经验派：见多识广理论派：原理清晰
💡 设计定位
物理模型不是要取代数据模型，而是与它并列成双引擎：用户选"物理 / 数据 / 双模型对比"三种模式。 两个引擎对同一段路各算一份氢耗，一致则互相印证，分歧大则把差异亮给用户看（透明 = 加分项）。 另外预留企业 MATLAB 高保真模型的可插拔接口——等企业数据模型到位，直接"拔掉我们的、插上他们的"。

2模型全景：五层能量流水线

氢气不是直接变成"车轮往前滚"的。它先被燃料电池变成电，电经过电机变成机械能，机械能经过传动到车轮，最后才去克服滚动阻力、空气阻力、坡度阻力和加速阻力。能量每过一道手都会"漏掉"一点（效率 < 100%）。物理模型就是把这条流水线一层一层算清楚：

图 1 · 能量流水线。氢气化学能 → 燃料电池发电 →（动力电池削峰/再生回流）→ 电机传动 → 车轮克服四阻力。

对应到计算流程，模型分 5 层，每一层的输入输出都是上一层的输入：

输入：SegmentData[]（里程 s / 均速 v̄ / 坡度序列 / 海拔 / 温度 / 道路等级 / 行为区概率 / 载重 m） │ L1 路段能量矩积分：把"一段路"按坡度切成"坡段"，逐坡段做能量积分 → E_wheel（轮边机械能） │ L2 纵向动力学：四阻力 + 海拔空气密度修正 + 旋转质量 + 再生制动回收 → P_wheel(t) │ L3 动力总成：P_drive = P_wheel/(η_m·η_dt) + P_aux(T)；电池削峰 → P_fc 工作点 │ L4 燃料电池效率：Larminie–Dicks 极化曲线 → η_fc(P, T) → 氢气质量流率 │ L5 氢耗折算 + 校准：LHV 效率法 ⊕ 法拉第定律双口径 → 三重锚点校准 k_cal │ 输出：每段氢耗 kg + 总氢耗 + 百公里氢耗 + 分项能量 + 敏感性

下面逐层展开。每层都先给严谨公式，再配一张图和一个"老奶奶能听懂"的比喻。

3第 1 层 · 路段能量矩积分（坡度怎么切、怎么合）

3.1 先回答一个尖锐问题：为什么"一段路只记爬坡/下降多少"不够？

你最关心的问题："一段路只记录爬坡和下降多少，但分开爬坡和连在一起爬坡最后的耗氢应该不一样"——对，完全正确。原因藏在两个地方：

为什么不一样物理本质均速×均坡的粗模型能量矩积分（本设计）
动能"存钱罐"下坡加速时把重力给的势能存成动能，紧接着的上坡再把动能花掉；连着的长上坡没有"预存动能"，只能靠电机硬拉完全忽略动能项动能项 δm·Δ(v²)/2 逐坡段结算
速度-坡度耦合上坡时车速下降 → 空气阻力按 v² 快速变小；用"均速"算会把这段的阻力算偏v̄² 一刀切用 E[v²]=v̄²+σ² 修正 + 坡段细分
下坡回血下坡的重力做功可以再生回收回电池，均速模型当它不存在不考虑再生制动回收模块显式建模
👵 老奶奶版 · 爬山能量账本

奶奶，把车想成一个背着氢气罐的登山客。登山客花力气（氢）分两种：往上爬（克服重力）和平路跑（克服摩擦和风）。
· 如果先下一段坡再爬一段坡：下坡时他根本不用费力，反而越走越快，相当于"白捡"了速度（动能存钱罐存满了钱），爬坡时把存的钱花掉——这笔账很划算。
· 如果是一段长长的上坡：没有下坡给他"存钱"，从头到尾都得自己出力气——同样总爬升高度，这笔账就贵得多。
· 中间坡怎么"切成小段"再"拼起来"算，就是看他把存钱罐用得多聪明。重力是"老实人"（势能只看你总爬了多高），但风和速度是"精明的账房"——路怎么弯、坡怎么断，它们算出来的钱不一样。
所以我们的模型不满足于"这段路爬升 300 米、均速 70"，而是把路段切细、把每段的速度和坡度一起算账。这就是"能量矩积分"。

3.2 能量矩积分：一段路的"能量账本"

把第 k 段路再切成 J 个坡段（每段坡度基本不变、只上坡或只下坡，由切分算法产出），轮边机械能是四笔账的和：

E_{wheel,k} \;=\; \underbrace{C_{rr}\, m\, g\, s_k}_{\text{①滚动}} \;+\; \underbrace{\tfrac12 \rho C_d A\, E[v^2]\, s_k}_{\text{②空气}} \;+\; \underbrace{m g\, \Delta h_k}_{\text{③坡度}} \;+\; \underbrace{\tfrac12 \delta m\, \Delta(v^2)}_{\text{④动能}}
项含义关键点
① 滚动阻力 C_rr·m·g·s轮胎压地摩擦发热跟载重 m和里程 s成正比——重卡半挂最重的一笔账之一
② 空气阻力 ½ρCdA·E[v²]·s撞开空气E[v²]=v̄²+σ²，σ 是段内速度波动——走走停停同样均速更费氢
③ 坡度 m·g·Δh爬升/下落的势能只跟高程差有关，与怎么切无关（重力是保守力）
④ 动能 ½δm·Δ(v²)起终点速度变化Δ(v²)=v_end²−v_start²，可正可负；坡度切分越细，此项越准
🔑 关键洞见（本设计的理论支点）

重力是保守力：只要起点和终点海拔定了，势能这一笔账（mgΔh）跟中间怎么爬完全无关。但空气阻力和动能是"路径相关"的——中间坡怎么断、速度怎么变，它们算出来的数不一样。
所以切分算法（坡度变化率 > 阈值就切、每段只上坡或只下坡）的真正科学意义是：把"路径相关的两项"算准。切得越细，段内坡度越接近常数、速度分布越接近真实，E[v²] 与动能交换的估计就越准。
这与 2026 年 Li 等在 Journal of Cleaner Production / ECM 提出的"坡度耦合工况合成"思路一致——重卡能耗代表工况必须显式携带坡度信息，否则高估/低估可达两位数百分比。

3.3 坡段怎么切（衔接已有切分算法）

图 2 · 路段 → 坡段。蓝色折线是真实纵剖面，虚线把坡度符号变化 / 变化率过大的位置切开，每段标注坡度值。

切分规则（已有算法的科学版表述）：

对第 k 段路（已含 GPS 高程序列）： step 1 计算逐点坡度 g_i = Δh_i / Δs_i； step 2 在坡度变号处强制切开（上坡/下坡不混在同一坡段）； step 3 在坡度变化率 |g_{i+1} − g_i| / Δs_i 超过阈值处切开（≤ 1~2% 每百米，可配置）； step 4 对过短的坡段（< 50 m）并入相邻坡段（避免数值噪声），但保持总高程差不变； step 5 输出坡段序列 {(Δs_j, θ_j, v̄_j)} → 喂给能量矩积分。
✅ 这样做保证了什么
每段内坡度近似常数 → ③坡度项按 mg·Δh 精确结算；②空气阻力用该坡段的 E[v²]；④动能项只在坡段边界结算。 总账在坡段之间"闭合"：把 J 个坡段的 ③加起来必然等于 m·g·(终点海拔−起点海拔)，不会丢能量。

4第 2 层 · 纵向动力学四阻力

4.1 从"能量"到"功率"

能量账本算的是一趟要多少焦耳；功率账本算的是某一瞬间要多大功率——燃料电池和电池是按"功率"分配工作的，所以还得把每个坡段的受力写成逐时刻形式：

F_{wheel}(t) \;=\; \underbrace{C_{rr}\,m g\cos\theta}_{\text{滚动}} \;+\; \underbrace{\tfrac12 \rho(H)\, C_d A\, v^2(t)}_{\text{空气}} \;+\; \underbrace{m g\sin\theta}_{\text{坡度}} \;+\; \underbrace{\delta\, m\, a(t)}_{\text{加速}},\qquad P_{wheel}=F_{wheel}\cdot v
符号含义取值 / 说明
m整车质量 = 整备 + 载重满载 49 t；整备 <10 t（H49 2.0）；载重用户输入
C_rr滚动阻力系数0.006~0.012，默认 0.009（重载卡车典型）
ρ(H)空气密度（随海拔修正）海平面 1.225 kg/m³；乌兰察布 1372m 比天津约低 15%
C_d · A风阻系数 × 迎风面积C_d=0.35（H49 官方），A≈7.5 m²（Class 8 平头牵引车）
θ坡度角θ = atan(grade/100)，grade 为百分比
δ旋转质量换算系数≈1.05（含车轮/传动系转动惯量）

4.2 海拔修正空气密度（相对 FASTSim 默认工况的改进）

\rho(H) \;=\; 1.225 \times \bigl(1 - 2.25577\times10^{-5} H\bigr)^{4.25588}

H 是路段平均海拔（米）。国际标准大气模型。平原（几十米）到高原（一两千米）空气密度差可达 10%~15%，直接修正风阻项。这条数据我们系统里已经有了（DEM 高程），不用额外抓取。

4.3 等效摩擦角：什么时候"下坡白捡"、什么时候"下坡要刹车"

把坡度阻力与滚动阻力比一比，会冒出一个很有意思的临界坡度：

\theta_c \;=\; \arctan(C_{rr}) \;\approx\; 0.5^\circ \;\text{（约 0.9\% 坡度）}
下坡坡度重力沿坡分量 vs 滚动阻力车会怎样模型怎么处理
0 < θ < θ_c（缓下坡）重力 < 滚动阻力仍需轻微驱动正常按阻力公式算
θ = θ_c重力 = 滚动阻力松油门能匀速滑行轮端功率 ≈ 0
θ > θ_c（陡下坡）重力 > 滚动阻力越滑越快，必须制动先再生回收，回收上限见 4.4

这个"摩擦角"概念来自经典车辆动力学（Gillespie 1992；余志生《汽车理论》），它把"下坡到底是省还是费"讲得明明白白：缓下坡省的是滚动阻力的钱，陡下坡才真正"白捡"重力能（且要防超速）。

4.4 再生制动回收（带 SOC 门限）

E_{regen} \;=\; \min\!\Bigl(\,\eta_{regen}\cdot E_{brake},\;\; E_{avail}(SOC)\,\Bigr),\qquad \eta_{regen}\approx 0.6\sim0.7
项说明
E_brake减速段动能损失 + 陡下坡需耗散的机械能
η_regen回收链路效率（电机发电→电池），0.6~0.7 文献典型值
E_avail(SOC)电池还能"吃"进多少电。SOC 高 → 回收受限 → 只能机械制动（这是"下坡并不总能省钱"的物理原因）
👵 老奶奶版 · 下坡

奶奶，下坡就像下楼梯。楼梯不陡的时候你慢慢走还省力；楼梯很陡的时候你不得不一路扶着栏杆（刹车）。"再生回收"就像在楼梯口装了个发电机，下楼梯的力气顺便发了点电。但如果楼下的充电宝已经满了（SOC 高），发电机再发也没地方存，只能让刹车片干磨（机械制动）。所以模型里，回收多少不是拍脑袋，而是看坡度够不够陡 + 电池还有没有空位。

5第 3 层 · 动力总成：传动效率 + 附件功耗 + 电池削峰

5.1 从"轮边功率"到"电堆该出多少电"

轮边功率是机械能，但电机吃的是电。中间隔着电机效率 η_m（负载率相关）和传动效率 η_dt；另外车上还有空调、气泵、转向泵、散热风扇这些"附件"一直在耗电——它们不产生前进动力，但必须喂饱：

P_{drive}(t) \;=\; \underbrace{\frac{P_{wheel}(t)}{\eta_m(P_{load})\cdot\eta_{dt}}}_{\text{驱动电功率}} \;+\; \underbrace{P_{aux}\bigl(T(t)\bigr)}_{\text{附件功耗}}
环节取值说明 / 来源
传动效率 η_dt0.92~0.94H49 官方公布传动效率 94%；行业典型 0.92
电机效率 η_m轻载 0.88 / 中载 0.93 / 重载 0.90永磁同步电机负载率效率表（文献典型值）
附件 P_aux2~8 kW，随温度NRC《21st Century Truck Partnership》：干线卡车附件 3~5 kW；极寒热管理可达 10 kW

5.2 附件功耗的温度耦合（天气数据直接进模型）

P_{aux}(T) \;=\; \mathrm{clip}\!\Bigl(P_0 + k_T\,|T - 20^\circ\mathrm{C}|,\;\; 2,\;\; 8\Bigr)\ \mathrm{kW},\qquad P_0=3\ \mathrm{kW},\ k_T=0.15\ \mathrm{kW/^\circ C}

这条公式的设计动机：我们系统已经能从 QWeather / ERA5 抓到每段路的实时温度。温度直接决定：

场景附件功率变化物理原因
常温 20℃≈3 kW（基础负荷）气泵、转向、低压电子设备
夏天 35℃≈5.3 kW驾驶室空调 + 散热风扇功耗上升
冬天 −15℃≈8 kW（上限）座舱 PTC 加热 + 电池/电堆保温
🔑 为什么要单独建模附件功耗？

对重卡，附件功耗 3~8 kW 看似不大，但折算到氢耗：1 kg 氢气 ≈ 33.3 kWh，8 kW 跑 1 小时 ≈ 0.24 kg。一趟 500 km 高速（约 7 小时）附件就要吃掉 ≈1.7 kg 氢气，相当于总氢耗的 5% 上下。极寒天气这个占比还能翻倍——不建模就漏账。

5.3 电池削峰 + SOC 平衡（简化 ECMS，不用逐秒优化）

氢电混合动力的分工本质：燃料电池负责"平均功率"，电池负责"尖峰与回血"。我们不做逐秒 MPC（那超出准静态范畴），用一条削峰规则 + 一个等效氢耗平衡项：

P_{fc}(t) \;=\; \mathrm{clamp}\!\Bigl(P_{drive}(t),\ \ P_{fc}^{min},\ \ P_{fc}^{max}\Bigr),\qquad P_{bat}(t)=P_{drive}(t)-P_{fc}(t)
\dot m_{H_2}^{eq} \;=\; \dot m_{H_2}^{FC} \;+\; \lambda \cdot \frac{P_{bat}}{\eta_{bat}},\qquad \lambda=\lambda_0 + k_\lambda\,(SOC_{target}-SOC)
项含义
P_fc^min / P_fc^max电堆最低稳定功率（约 10% 额定）与最高允许功率——让电堆总在高效区
λ等效因子：把"电池的电"折算成"本来要烧多少氢气"（Zheng 2012 / Sun 2022 ECMS 思想）
SOC_target − SOCSOC 平衡项：电量低了 λ 变大 → 电堆多出力顺便充电；高了 λ 变小 → 电池多出力
长路段约束全程 SOC 终值 ≈ 初值（不把"电池偷的电"算成免费氢耗，账目公平）

这比 Ahn & Rakha 2022 的"4 段功率阈值规则"更进一步：把电池电量纳入等效氢耗账本，避免"先耗尽电池再烧氢"造成的假省氢。同时比完整 MPC 简单得多，纯前端毫秒级可算。

5.4 载重显式建模（重卡氢耗的第一敏感因素）

m \;=\; m_{curb} + m_{cargo},\qquad E_{roll} \propto m,\quad E_{grade} \propto m
图 3 · 载重敏感性示意。滚动阻力与坡度阻力都正比于总质量 m，载重是重卡氢耗最大的"旋钮"。

用户在前端输入载重（空载/半载/满载或自定义吨数），物理模型把 m 直接代进公式——这是数据模型最头疼、物理模型最拿手的地方。

6第 4 层 · 燃料电池效率（极化曲线）

氢气不是"一烧就全变成电"。燃料电池的效率随输出功率像一座山丘：轻载和满负荷都低，中间有个"最舒服"的高效区。这个形状来自电化学极化曲线：

6.1 Larminie–Dicks 极化曲线（底层电化学）

V_{cell}(i) \;=\; E_{oc} \;-\; A\,\ln(i) \;-\; R\,i \;-\; m\,\exp(n\,i)
项物理含义
E_oc开路电压（无电流时单电池电压，约 0.95~1.0 V）
A·ln(i)活化过电压：让反应"启动"要付的代价（对数项，小电流时占主导）
R·i欧姆过电压：质子膜和导体的电阻（线性项，中等电流主导）
m·exp(n·i)浓度过电压：大电流时氢气供不上（指数项，大电流主导）

6.2 从"电压"到"效率"

\eta_{stack}(P) \;=\; \frac{V_{cell}}{1.253},\qquad \eta_{fc}(P) \;=\; \eta_{stack}(P)\times\eta_{BOP},\qquad \eta_{BOP}\approx 0.85\sim0.90

1.253 V 是氢燃料电池的LHV 当量电压（ΔH_LHV/(2F) = 241.8 kJ/mol ÷ 2×96485 C/mol）。电压越接近 1.253 V，电化学效率越高。再乘上系统辅机（空压机、水泵、散热）的效率 η_BOP，就得到系统效率。现代 PEM 系统峰值系统效率约 50%~55%，正好对上海珀特官方公布的"燃料电池系统综合效率 >55%"。

图 4 · 极化曲线（蓝）与系统效率曲线（橙）。效率在中等负荷达到峰值，两端的"启动费"和"供气不足"都会拉低效率——这正是电池削峰的意义：让电堆总待在山丘顶部。

6.3 温度与海拔对效率的修正

\eta_{fc}(P,T,H) \;=\; \eta_{fc,0}(P)\times \underbrace{\bigl(1 - k_{T}^{loss}\,|T - T_{ref}|\bigr)}_{\text{低温损耗}} \times \underbrace{\bigl(1 - k_{H}\,(H/H_{ref})\bigr)}_{\text{高海拔空压机负荷}}

低温时电堆活性下降、需要保温，η 下降；高海拔空气稀薄，空压机要更卖力压气（BOP 功耗上升）。这两条修正都直接消费我们系统已抓到的温度和海拔数据。

👵 老奶奶版 · 山丘

奶奶，燃料电池就像一个烧柴的锅炉：火太小，光顾着生火不产热（轻载效率低）；火太旺，柴还没烧透就冒黑烟（重载效率低）；不紧不慢地烧（中等负荷），同样的柴产的热最多。所以聪明的司机让锅炉一直保持"中火"，需要猛劲时让旁边的充电宝（电池）顶上——这就是"电池削峰"的全部意义。

7第 5 层 · 氢耗折算与三重锚点校准

7.1 双口径折算（互相查账，防止模型"自嗨"）

\textbf{口径 A（LHV 效率法）}\quad m_{H_2,k} \;=\; \sum_j \frac{P_{fc,j}\cdot \Delta t_j}{\eta_{fc}(P_{fc,j})} \;\Big/\; LHV_{H_2},\qquad LHV_{H_2}=120\ \mathrm{MJ/kg}=33.33\ \mathrm{kWh/kg}
\textbf{口径 B（法拉第定律）}\quad \dot m_{H_2} \;=\; \frac{M_{H_2}\cdot N_{cell}\cdot I_{stack}}{2F},\qquad I_{stack}=\frac{P_{fc}}{N_{cell}\cdot V_{cell}}
口径思路数据要求
A · LHV 效率法电堆输出电能 ÷ 效率 ÷ 氢热值η_fc(P) 曲线 + 电功率
B · 法拉第定律每个电子对应 1/2 个氢分子（电荷守恒）电流 I、单电池数 N、电压 V

当极化曲线与效率曲线自洽时，两口径结果差异应 < 3%。实现时两边都算、互相比对——这是"不造假"的工程化保障。

7.2 三重锚点校准（让模型站在官方实车数据的肩膀上）

纯物理公式难免有参数偏差（滚阻、附件、效率曲线的系数）。我们用海珀特官方实车数据标定一个综合修正系数 k_cal，而不是拍脑袋调参：

k_{cal} \;=\; \frac{\text{官方锚点氢耗}}{\text{模型初算氢耗}\bigl(\text{同工况}\bigr)},\qquad \hat m_{H_2} \;=\; m_{H_2}^{raw}\times k_{cal}
锚点数值工况来源（均已核实）
A · 官方发布≤8 kg/100km满载 49t、高速2023-12 全球首发（北极星氢能网 / 21 经济）
B · 交付口径7.8 kg/100km满载 49t、高速、续航 1000km2024-08 武汉晚报；湖北日报小批量交付
C · 2.0 实车验证≤7.1 kg/100km满载 49t、均速 75km/h（青岛—天津、武汉—宜昌）2025-11 北京氢能创新中心；2026-06 CEO 访谈
🔑 校准的"诚实设计"

界面永远同时展示 纯物理值 与 校准值 两组数字，并在数据来源状态条里标注"已用官方锚点校准"。 k_cal 是一个全局标量（不随路段变化），只负责把系统性的参数偏差拉回来；路段之间的差异仍然完全由物理公式决定——不会出现"校准把路况差异都抹平"的造假式拟合。

⚠️ 已知边界（诚实披露）
准静态模型对"秒级瞬态"（电堆动态响应、热管理延时）不敏感；对驾驶风格（激进/平稳）只能通过速度波动 σ 间接体现。预期整段精度 ±10% 内、常 ±5% 内（NREL FASTSim 官方口径，SAE 2022-01-0556）。企业 MATLAB 高保真模型接入后，通过 adapter 升级到 L3 瞬态精度。

88 个创新点一览（对比传统做法）

创新点传统准静态做法本设计解决的问题 / 依据
① 路段能量矩积分均速 × 均坡 × 时间坡段切分 + 四项能量积分（含动能项）"分开爬坡 vs 连续爬坡"氢耗不同；保守力/路径相关力分开算
② 速度波动修正 E[v²]v̄² 一刀切E[v²]=v̄²+σ²，σ 来自行为区概率走走停停同样均速更费氢；行为区（停止/启动/减速）数据直接利用
③ 等效摩擦角 θ_c坡度一律线性叠加θ_c=arctan(C_rr) 分"缓下坡/临界/陡下坡"明确下坡何时免费、何时需制动（Gillespie / 余志生）
④ 再生制动 + SOC 门限下坡直接算负功E_regen=min(η·E_brake, E_avail(SOC))SOC 高时回收受限——"下坡并非总能省钱"
⑤ 温度-附件-电堆耦合附件功率写死 3~4 kWP_aux(T) 2~8 kW + η_fc(T,H) 修正直接把 QWeather/ERA5 温度、DEM 海拔喂进公式（NRC 3~5kW、极寒 10kW 依据）
⑥ 载重显式建模模型按固定总质量m=m_curb+m_cargo，前端可输入滚阻/坡度 ∝ m；重卡载重是第一敏感因素
⑦ 简化 ECMS 的 SOC 平衡固定功率阈值分配削峰规则 + λ 等效氢耗 + SOC 终值约束避免"先耗电池再烧氢"的假省氢（Zheng 2012 / Sun 2022）
⑧ 双口径折算 + 三重锚点校准单公式 + 手工调参LHV 效率法 ⊕ 法拉第定律交叉验证；官方 7.1/7.8/8.0 锚点标定 k_cal；纯物理值 & 校准值并列展示不造假、可对标、可复现；企业模型可插拔
一句话总结
传统模型"用平均把细节抹平"，本设计"把细节切出来分别算准、再拼回去"——切（坡段）→ 分（四项能量）→ 补（波动/温度/SOC）→ 校（官方锚点）。每一处都有物理依据与文献出处，没有拍脑袋参数。

10怎么验证它没算错（验收路径）

验收 1 · 金样 B 复现：H49 × 济青高速 340km × 载重 34.11t × 氢价 30 → 目标：单趟氢耗 26.52 kg（=7.8 kg/100km），单趟 1796 元 / 柴油 1925.2 元 / 节省 129.2 元 验收 2 · 三重锚点区间：满载 49t、高速 75km/h 工况 → 模型输出 ∈ [7.1, 8.0] kg/100km 验收 3 · 双引擎对比：与 HistGB 数据模型在同一批线路上对比，差异 >20% 时提示用户（不藏丑） 验收 4 · 敏感性 tornado：坡度 / 载重 / 均速 / 温度 / 路况各 ±10% → 画 tornado 图，检查方向是否物理合理 验收 5 · 开源对照：与 NREL FASTSim（同参数、CHTC-TT 工况）对照量级；与 OPEM 极化曲线交叉验证
误差来源排序（预期）
坡度 > 载重 > 合成工况 vs 实际驾驶 > 附件功耗 > 路况 > 海拔空气密度。 坡度误差已被"坡段切分"显著降低；"合成工况 vs 实际驾驶"是准静态模型的天花板，通过分段巡航 + 行为区概率近似控制，并在界面如实披露。
