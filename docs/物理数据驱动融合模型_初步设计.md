# 物理 + 数据驱动融合模型 · 初步设计（待开发）

> **一句话**：做一个"隐藏层每个节点都有物理名字"的神经网络——输入（天气/路况/载重）先决定**电堆功率、电机功率、电池功率、附件功率**这些车辆内部物理量，再由它们算出氢耗。物理保证结构可解释，数据保证非线性精度。
> **状态**：🔜 已完成文献调研与初步设计，**待开发**（未接入前端预测引擎）。
> **日期**：2026-08-23 ｜ 关联：`docs/物理氢耗模型_设计方案.html`、`ml/physics.py`、`ml/predict.py`

## 1. 动机：为什么值得做

现有两条引擎各有一块盲区：

| 引擎 | 强项 | 盲区 |
| --- | --- | --- |
| 机器学习 HistGB | 拟合能力强、能吃下所有可抓取特征 | 黑箱，中间过程不可解释；小样本下容易过拟合 |
| 物理模型（能量守恒） | 每一步可解释、不依赖训练数据、外推稳 | 假设死板（η_fc 恒 0.5、附件公式简化、电池策略简化），**不会用实车数据自我修正** |

本设计想补的，正是两者之间那块地：**用神经网络拟合"输入 → 车辆内部物理量"的映射，同时让隐藏层节点就是物理量本身**。这既保留了物理的可解释性（中间变量全部有名有姓、可在前端展示），又能用实车数据校准物理假设（比如 η_fc 其实随负载/温度变化）。

用户原始想法的严谨化：不是"拿电流降维当隐藏层"（新路线拿不到电流，是死路），而是"**预测**内部物理量当隐藏层"（输入全可抓取，内部量是预测出来的，照样可解释）。

检索结论：**"理论约束神经网络 + 模块化可解释性"正是 2025 年前后的热点**，且已出现与 H49 同类的"燃料电池电动卡车能耗建模"直接对标论文。

## 3. 核心架构：可解释隐藏层 = 物理量

```
输入层（全部可抓取）
 里程 s / 均速 v̄ / 坡度 θ / 海拔 H / 温度 T
 风速·风向 / 湿度 / 道路等级 / 载重(→总质量 m) / 时段 hour
            │
            ▼  第 1 阶段：神经网络（学出来的权重）
┌──────────────────────────────────────────────┐
│  隐藏层：有名有姓的车辆内部物理量（可解释）          │
│  轮边功率 P_wheel、电堆功率 P_fc、电池功率 P_bat、  │
│  附件功率 P_aux、电堆效率 η_fc（可选）、SOC（可选） │
└──────────────────────────────────────────────┘
            │
            ▼  第 2 阶段：能量守恒（公式，或小头网络）
  氢耗  m_H₂ = P_fc · t / (η_fc · LHV)
```

关键点：
1. **隐藏层不是"黑箱隐变量"，是物理量**——预测完可以直接在表格里展示"这段路电堆功率预计 87.9kW"，评审/用户都能看懂；
2. **输入全部可抓取**（复用现有 SegmentData 接口），新路线照样能跑；
3. **第 2 阶段优先用公式**（能量守恒），只有 η_fc 等参数可以学习——这样模型永远不会输出"违背能量守恒"的结果。

## 3.5 中间层变量设计：80 列 → 13~15 个物理量（数据实证版）

> 基于两辆 H49 实车 60s 清洗数据（各 80 列）的实证分析，把"内部 80 列 → 中间层 Z"的降维方案敲定：**用物理归并合成 13~15 个有名有姓的物理量，不用无监督 PCA**。本小节固化变量清单与归并映射，作为后续训练/预测的依据（2026-08-29 更新）。

### 3.5.1 三条实证结论（为什么不用 PCA）

1. **80 列高度冗余**：FC 电流组（4 列）平均 |r|=0.998、电机电流组（3 列）=0.999、氢瓶温度组（6 列）=0.976——大量列是同一个信号。
2. **无监督 PCA 浪费信号**：80% 方差要 7 个主成分，但只有 PC1（r=+0.672）和 PC5（r=+0.427）与氢耗相关；原始 80 列直接线性回归 CV R² 崩塌到 -443（共线性爆炸）。
3. **物理归并更优**：P_FC（V×I 合成）与氢耗 r=0.807，几乎追平原始 FC 电流（0.812），却把 4 列并成 1 列且有了物理含义。

### 3.5.2 保留的中间层变量（Z）与来源

| 组 | 变量 | 来源 | 与氢耗 r |
| --- | --- | --- | --- |
| 路线 | 车速 v | 路段均速 + v-t 工况合成 | 0.14 |
| 路线 | 纵向加速度 a | v(t) 差分 a=Δv/Δt（加速度列清洗错位，弃用，改用速度差分） | 0.35 |
| 物理仿真 | I_FC 燃料电池总电流 | FC 电流 A+B 求和；预测端由物理模型按 I=P/V 反算 | 0.81 |
| 物理仿真 | V_FC 燃料电池电压 | FC 电压 A/B 均值 | — |
| 物理仿真 | P_FC 燃料电池总功率 | Σ(FC 电流×电压)；预测端=功率需求−电池削峰后的 FC 出力 | 0.81 |
| 物理仿真 | P_电机 驱动功率 | 三电机 Σ(V×I)（后桥L/R + 中桥） | 0.52 |
| 物理仿真 | P_附件 附件功率 | Σ 气泵/风扇/油泵/水泵/空调压缩机 | 0.31 |
| 物理仿真 | P_电池 电池功率 | V_bat×I_bat（缓冲池，r≈0 但保留作状态） | ~0 |
| 物理仿真 | SOC | 电池模型积分 | -0.44 |
| 热/氢 | T_电堆出口温度 | 热模型（负载+冷却） | 0.63 |
| 热/氢 | T_瓶温 | 热模型（≈环境温度） | 0.34 |
| 合成 | P_整车电功率 | P_电机 + P_附件 | 0.57 |
| 合成 | η_FC 电堆效率 | **只能由物理模型输出**（P_FC ÷ 化学能输入），不能由目标反推 | -0.28 |
| 可选 | 低压压力 / T_电堆入口温度 | 物理/热模型（信息量小，可留可丢） | — |

### 3.5.3 舍弃清单（75 特征列的去向）

| 去向 | 数量 | 明细 |
| --- | --- | --- |
| 纯控制状态标志（含常量列） | 12 | runModel、signalState、velGear×3、dcdc_highPre_status×2、fcWorkState×5（其中 fcWorkState_3 全行相同） |
| 元数据 | 4 | time / lat / lon / VIN（查询键，不进 Z） |
| 不可靠加速度列 | 1 | H49Data_longitudinal_acc（清洗错位，弃用，改用速度差分） |
| 归并进合成量 | 33 | FC 电流电压+DC 输出（8）→P_FC/I_FC/V_FC；三电机电流电压（6）→P_电机；附件电流电压功率（9）→P_附件；氢瓶温度（6）→T_瓶温；电堆进出口温度（4）→T_堆 |
| 低价值细节 | 17 | DCDC 电流电压（4）、PTC/氢泵电压（3）、DC/空压机温度（4）、高圧DCDC温度（1）、冷却液电导率（2）、2#温度采样（1）、氢系统最高温度（1）、氢气最高压力（1） |
| 泄漏（仅展示，不进特征） | 2 | h2_remain（氢耗积分）、高压压力（与 h2_remain 相关 r=0.997） |

### 3.5.4 泄漏红线（务必遵守）

- **h2_remain 及其同源量一律不进特征**：h2_remain 是氢耗积分；高压压力（瓶压）与 h2_remain 相关 r=0.997，同为泄漏量。两者只能用于前端展示/评测，不能作为模型输入。
- **η_FC 不能由目标反推**：η = P_FC/(氢耗×LHV) 若用训练目标算即为泄漏；只能由物理模型输出。
- **电流类特征绝不能进输入层（见 §6）**：Z 里的电流/功率是"中间层"；训练端可用实车测量值，预测端必须用物理模型算出的值，两侧口径必须一致。

### 3.5.5 实验验证结果（2026-08-29，ml/dim_reduce_experiment.py）

按行程分组 5 折 CV（防止相邻 60s 泄漏），HistGB 预测氢耗：

**① 60s 级（目标 h2_consum_per_sec, kg/60s）**

| 特征集 | R² | RMSE |
| --- | --- | --- |
| **Z 物理量（12）** | **+0.651** | 0.0333 |
| ACQ 路线可抓取（6） | +0.063 | 0.0547 |
| Z + ACQ（17） | +0.643 | 0.0337 |
| 原始 75 列（Ridge 参考） | -0.225 | 0.0518 |

**② 5km 段级（目标 h2_per_km, kg/km，与现有基线同口径）**

| 特征集 | R² | RMSE (kg/km) |
| --- | --- | --- |
| 基线 ACQ+DEEP（现有） | +0.421 | 0.0444 |
| **Z 物理量（12）** | **+0.831** | 0.0234 |
| Z + ACQ | +0.846 | 0.0225 |
| Z + ACQ + DEEP（全） | **+0.872** | 0.0209 |

**结论**：
1. **降维方案有效**：段级 R² 从现有基线 0.421 提升到 **0.872**（RMSE 减半），60s 级 Z 单独即 0.651，而路线可抓取特征仅 0.063——中间物理量确实携带氢耗信息；
2. **I_FC 是绝对主力**：置换重要性 0.552（远超第二的 T_stack 0.078），物理主线"FC 电流/功率 → 氢耗"成立；
3. **原始 75 列线性崩塌（R²=-0.225）**再次印证共线性，降维是必要的；
4. **诚实边界**：本实验验证的是第 1 阶段"Z→氢耗"（Z 用实车测量值）；上线时 Z 须由物理模型算出，最终精度取决于物理模型对 P_FC 等的仿真精度——这是第 2 阶段的挑战。


**阶段二模型选定（2026-08-29）**：阶段二最终模型用**非树模型 Ridge**（不用神经网络——MLP 在小样本上崩盘 R²=-0.77；也不用树——Ridge 系数可解释、答辩好讲）。`ml/train_ridge.py` 用 **Z+ACQ+DEEP（33 特征）** 训练，按行程分组 5 折 CV：**R²=0.762 ± 0.066，RMSE=0.0281 kg/km**；已保存 `ml/model_ridge.joblib` + `ml/ridge_meta.json`（含原始量纲系数）。注意：Z 内部各物理量共线性较高，单系数符号不宜过度解读；上线时 Z 由物理模型仿真提供（见 §4/§3.5.4）。

## 4. 两个监督源：中间量没有标签怎么办

隐藏层物理量（P_fc 等）在**新路线上**没有实测值，训练时却需要"标准答案"。两个老师：

| 监督源 | 怎么得到标签 | 作用 |
| --- | --- | --- |
| **物理模型当老师（蒸馏）** | 用 `ml/physics.py` 对每个训练段生成 P_wheel/P_fc/P_bat/P_aux 的"标准答案" | 让网络先学会"复述物理"，保证结构可靠、外推不飘 |
| **实车 CSV 当老师（校准）** | 车辆1/车辆2 数据里 电流×电压 → 真实功率（电堆输出电流×电压、电机电流×电压、DCDC 等），按 60s 聚合口径对齐 | 让网络**修正物理假设**：η_fc 不是恒 0.5、附件不是那么死板、电池削峰更真实 |

训练策略（两步或联合）：
- **两步法（推荐先做）**：① 用实车功率标签微调物理参数（如拟合 η_fc 随功率/温度的变化曲线）→ ② 再用物理伪标签训练"输入→物理量"网络；
- **联合法（进阶）**：网络同时吃两个监督源，损失 = α·物理一致性损失 + β·实车功率损失 + γ·最终氢耗损失。

红线：**监督源可以混，但输入绝不能混入电流类特征**（见 §6）。

## 6. 关键坑与红线（务必遵守）

1. **电流类特征绝不能进输入层**：电堆/电机/DCDC 电流与氢耗是同一能量流的"果"（法拉第定律），新路线拿不到，进输入=预测失效。这条是上一版方案的死穴，已写进文档防止回潮。
2. **别变成"物理复读机"**：如果监督只靠物理蒸馏，网络学到的就是物理模型的近似——白干。必须让**实车真实功率**占足够权重，让网络有"自己的想法"。
3. **小样本过拟合**：段级数据约 1000 段，神经网络必须强正则（Dropout/早停/权重衰减）+ **按行程分组 CV**（与 HistGB 同口径，防止相邻 60s 泄漏），否则会出现虚高训练 R² 自欺欺人。
4. **单位/口径对齐**：训练目标是 h2_consum_per_sec（60s 级），预测目标是段级 kg/km——两者要统一到"段级"口径再训练（复用现有 5km 聚合特征管道）。
5. **数据可行性（已实测）**：车辆1 清洗后 1055 行 × 80 列，72 个数值列 PCA 前 10 主成分解释 88.7% 方差（降维空间大，但那是给"事后分析"用的，不是给预测输入用的）。

## 7. 预期与风险（诚实版）

- **精度**：§3.5.5 实验显示 **Z 物理量降维后段级 R²=0.872（远超现有 HistGB 0.421）**，但这是第 1 阶段（Z 用实车测量值）的上限；上线精度取决于物理模型对 P_FC 等的仿真精度（第 2 阶段）。真瓶颈在数据质量与物理模型仿真精度。
- **价值**：① 中间量全部可解释（补黑箱短板）② 用实车数据校准物理假设 ③ 三引擎交叉验证 + 答辩故事（ML / 物理 / 混合）。
- **风险**：监督源失衡 → 复读机；小样本 → 过拟合；实车功率回填口径不准 → 校准失效。每一条都有对策（§4/§6）。
