# 重卡车速对齐方案（临时：货车系数）

> **一句话**：预测端速度原来全部来自高德**轿车**驾车 API，整体偏高；现按道路等级乘**货车系数**（基于两辆 H49 实车数据标定）把速度对齐到真实重卡水平。**将来接入高德货车路径规划服务后，用真实重卡时长替换本系数。**
> **日期**：2026-08-29 ｜ 关联：`src/route/segment.ts`（`TRUCK_SPEED_FACTOR` / `truckSpeedKmh`）、`src/route/amapRoute.ts`、`scripts/amap_truck_test.py`

---

## 1. 背景：为什么速度会偏高

评审老师反馈：**预测车速整体偏高**。根因是数据来源错位：

| 环节 | 速度来源 | 口径 |
| --- | --- | --- |
| **预测端** | 高德驾车 API `v3/direction/driving` 的 `duration` → `avgSpeedKmh = 距离÷时长` | **小轿车**通行速度（按轿车限速+实时路况） |
| **训练端** | 实车 CAN 总线 `canData_speed`（×0.1 → km/h） | **真实重卡**速度 |

高德 `duration` 不区分货车，按轿车算。结果预测输入速度比真实重卡高出一截，既让物理模型按轿车功率算，也让 ML 模型输入偏离训练分布。

## 3. 临时方案：货车速度系数（已实现）

### 3.1 系数与封顶（`src/route/segment.ts`）

| 道路等级 | 系数（轿车速度×系数） | 速度封顶 km/h | 标定依据 |
| --- | --- | --- | --- |
| highway 高速 | 0.75 | 90 | 轿车典型 100~120 → 重卡中位 75 / P99~93 |
| expressway 快速路 | 0.75 | 85 | 介于高速与国道 |
| national 国道 | 0.80 | 80 | 轿车~90 → 重卡中位 68 |
| provincial 省道 | 0.80 | 70 | 轿车~75 → 重卡中位 59 |
| county 县乡道 | 0.80 | 70 | 重卡中位 62 |
| city 城市 | 0.85 | 60 | 轿车~45 → 重卡中位 34 |
| other 其他 | 0.80 | 80 | 重卡中位 65 |

公式：`v_truck = min(封顶, max(5, v_car × 系数))`

### 3.2 时长同步拉长（口径一致性）

速度变慢，时长必须跟着变，否则 `距离÷速度≠时长` 会破坏下游口径：

- 段级：`durationH = distanceKm / v_truck`（`effDurationS`，见 `buildSegments`）
- 路线级：`durationH = distanceKm / v_truck`（`pathToCandidate`）

这样影响链全程自洽：**物理模型功率**（风阻∝v²）、**ML 的 v_mean 特征**（对齐训练分布）、**司机费用**（按小时）、**天气匹配时刻**（`weather.ts` 按 `durationH/2` 估计到达时间）都用同一套重卡速度/时长。

### 3.3 代码位置

| 文件 | 改动 |
| --- | --- |
| `src/route/segment.ts` | `TRUCK_SPEED_FACTOR` / `TRUCK_SPEED_MAX` / `truckSpeedKmh()` / `truckSpeedKmhRoute()`；`buildSegments` 里 `carSpeed → avgSpeed`（乘系数）并反推 `effDurationS` |
| `src/route/amapRoute.ts` | `pathToCandidate` 路线级均速/时长同步乘系数 |

> 兜底说明：`durationS == 0` 时用 `CRUISE_SPEED_BY_LEVEL`（本身就是重卡巡航速度），**不二次缩放**。

## 4. 未来：接入高德货车路径规划服务（替换本系数）

**目标状态**：用高德货车接口返回的真实重卡时长/速度，替换 §3 的系数。

- 接口：`https://restapi.amap.com/v4/direction/truck`（基础版）/ `v5/direction/truck`（高级版，当前 key 测试返回 `INSUFFICIENT_PRIVILEGES`）
- 官方文档：
  - 基础版：https://lbs.amap.com/api/logistic-service/guide/wagon_path/truck-route-plan-basis
  - 高级版：https://lbs.amap.com/api/logistic-service/guide/wagon_path/hc-route-plan
- 关键参数（H49）：`size=4`（重型车）、`load=49`（总重吨）、`weight=30`（核定载重吨）、`axis=6`、`height=4`、`width=2.55`
- 开通方式：**收费接口**，需到高德开放平台提交**商务合作类工单**申请试用/购买配额（有少量免费测试额度）
- 测试脚本：`python scripts/amap_truck_test.py lng,lat lng,lat`（读 `.env` 的 `AMAP_KEY`，返回路线级距离/时长/均速 + 分段明细）
- 接入改动点（开通后）：
  1. `amapRoute.ts` 新增 `fetchTruckPaths`（v4 响应结构：`data.route.paths`、`errcode/errmsg`，与 v3 的 `route.paths`/`status` 不同）
  2. 用货车 `steps[].duration` 替代轿车 duration，删掉 §3 的系数（或保留系数作兜底）
  3. 货车参数（size/load/weight/axis）从车型配置读入，支持用户选车型

## 5. 诚实边界

- 系数是统计标定，不是实时重卡路况；不同载重/坡度下真实速度会有波动，系数取的是中位口径。
- 坡度对重卡速度的影响（上坡降速）由物理模型的速度上限裁剪与工况合成兜底，系数只做道路等级层面的对齐。
- 接入高德货车 API 后，速度将按真实重卡限行/限速/政策计算，届时可去掉系数（或保留作无货车服务时的兜底）。
