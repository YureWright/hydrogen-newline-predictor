# 动态规划模块设计

## 路线 · 车速 · 氢电双补能 · 实时重规划

> 把系统从"预测这条线路要烧多少氢"，升级为"按你的**时间—费用偏好**，告诉你**走哪条路、每段开多快、在哪里加氢或充电**，并在行驶中根据实际偏差**自动调整规划**"。

**状态**：已实现（可运行 Demo）  
**日期**：2026-11-16  
**关联代码**：`scripts/dynamic_plan.ts`、`vite.config.ts`、`src/components/DynamicPlanPage.tsx`、`src/components/DynamicPlanPanel.tsx`

---

## 一、模块做了什么

| 能力 | 说明 |
| --- | --- |
| 路线规划 | 输入起终点，调用高德驾车路线 API，自动分段 |
| 路况与环境 | DEM 高程（坡度/海拔）+ QWeather 沿线天气（温度/风速/湿度） |
| 车速优化 | 逐段扫描车速，用物理模型算氢耗，选出广义成本最低的"经济车速" |
| 双补能规划 | 在路线走廊内匹配加氢站与充电站，用动态规划决定"在哪加、加多少" |
| 动态重规划 | 检测到路况偏差后，重新优化受影响路段，输出新的司机指令 |
| 实时监控 | 默认每 5 分钟轮询高德实时路况，延误超过阈值自动触发重规划 |

## 二、整体架构

```
┌─────────────────────────────────────────────────────────────┐
│ 前端（首页「动态规划」入口 / 路段分析页「动态规划」页签）        │
│  地址输入 · 偏好滑杆 · 偏差参数 · 结果可视化                    │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP
┌───────────────────────────▼─────────────────────────────────┐
│ 后端 API（vite.config.ts 中间件）                             │
│  /api/plan/start|status|result      规划任务（异步 job）       │
│  /api/monitor/start|status|stop     实时监控（定时轮询）       │
└───────────────────────────┬─────────────────────────────────┘
                            │ 子进程
┌───────────────────────────▼─────────────────────────────────┐
│ 规划内核（scripts/dynamic_plan.ts）                           │
│  路线分段 → DEM/天气 → 车速扫描(物理模型) → 站点匹配 → 双补能DP │
└─────────────────────────────────────────────────────────────┘
```

**为什么用异步任务？** 一次规划需要拉取路线、DEM 瓦片、天气并做上千次物理仿真，耗时约 30~90 秒。同步 HTTP 请求容易被网关或浏览器超时截断，因此采用「提交任务 → 轮询状态 → 取结果」的模式（与路段测算任务一致）。

## 三、规划内核流程

### 3.1 路线与分段

调用高德驾车路线 API 获取路径的 `steps`，按导航指令与收费/路况信息切分为路段序列（复用现有 A1 分段切片）。每段包含：里程、均速、道路等级、路况状态、变速行为等。

### 3.2 高程与天气

- **高程**：从 Terrarium DEM 瓦片采样，得到逐段平均坡度 `gradePercent`、平均海拔 `elevationM`；
- **天气**：按出发时间与沿线位置匹配 QWeather 逐小时数据，得到温度、风速、风向、湿度。

### 3.3 逐段经济车速

对每一段用物理模型计算不同速度下的百公里氢耗和广义成本。搜索采用
**5 km/h 全程粗扫 → 1 km/h 局部加密 → 0.2 km/h 局部精修**，
而不是只评估 5 km/h 网格或直接对 30~90 km/h 做 0.2 km/h 全量穷举。详见第四节。

### 3.4 走廊站点匹配

- 加氢站：`data/stations.geojson`（571 座，含 35/70MPa、价格、枪数）；
- 充电站：`data/charging_stations.geojson`（65,199 座，高德 POI 抓取）；
- 将站点投影到路线折线，保留走廊内站点（加氢 ≤8km、充电 ≤3km），同位置 1km 内合并为同一补能点。

### 3.5 氢电双补能 DP

以「站点序号、剩余氢量、电池 SOC」为状态做动态规划，求出全程最小广义成本，详见第五节。

## 四、车速优化模型

### 4.1 优化目标

对固定路线上的每一段，独立求解：

$$
\min_{v}\ m(v)\cdot\frac{L}{100}\cdot p_{H_2}+(c_d+\lambda)\cdot\frac{L}{v}
$$

符号含义：

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| $v$ | 车速 | km/h |
| $m(v)$ | 该车速下的百公里氢耗（物理模型计算） | kg/100km |
| $L$ | 路段里程 | km |
| $p_{H_2}$ | 氢价 | 元/kg |
| $c_d$ | 司机时薪 | 元/h |
| $\lambda$ | 用户时间价值（偏好参数） | 元/h |

### 4.2 车速约束

$$
v_{\min}=30\ \text{km/h},\qquad
v_{\max,i}=\min\left(v_{road,i},\ \max(1.1v_{AMap,i},40)\right)
$$

其中：

- $v_{road,i}$ 为按道路等级设定的重卡速度上限；
- $v_{AMap,i}$ 为高德该路段的实时平均速度；
- 重规划时可再把 $v_{\max,i}$ 乘以限速系数；
- 天气、坡度、温度等当前主要通过物理模型改变氢耗 $m(v)$，暂未单独生成速度硬上限。

### 4.3 物理模型

每段逐时刻计算行驶阻力与功率：

$$
F_{total}=F_{roll}+F_{aero}+F_{grade}+F_{acc},\qquad
P_{wheel}=F_{total}\cdot v
$$

$$
P_{drive}=\begin{cases}P_{wheel}/\eta_{mt}+P_{aux}, & P_{wheel}\ge 0\\ P_{wheel}\cdot\eta_{mt}+P_{aux}, & P_{wheel}<0\end{cases}
$$

电堆按功率跟随策略输出 $P_{fc}$，电池削峰填谷，最终由电堆电能换算氢耗：

$$
m_{H_2}=\frac{E_{fc}}{\eta_{fc}\cdot LHV}
$$

其中 $LHV=33.3\ \mathrm{kWh/kg}$，$\eta_{fc}$ 取 0.5。

### 4.4 为什么存在"经济车速"

| 速度偏低 | 速度偏高 |
| --- | --- |
| 附件功耗（空调、气泵、水泵）按时间摊到每公里上变多 | 风阻与速度平方成正比，功率与速度三次方成正比 |
| 单位里程氢耗偏高 | 单位里程氢耗急剧上升 |

因此中间存在最优车速。若把氢耗近似为 $m(v)=a+bv^2$，可推导：

$$
v^{*}=\left(\frac{c_d+\lambda}{2bp_{H_2}}\right)^{1/3}
$$

即**时间越值钱（$\lambda$ 越大），建议车速越高**。

> 实测说明：49 吨重卡的滚动阻力占主导，氢耗对车速的敏感度低于小型车，因此经济车速经常靠近限速上限；偏好主要改变的是**路线选择**与**补能策略**。

### 4.5 5 → 1 → 0.2 km/h 分层搜索

物理模型包含电堆最低功率、电堆最高功率、电池功率限幅、下坡再生和氢耗上限等分段逻辑，
因此成本曲线可能存在平台或折点，不能默认它处处光滑。当前不采用遗传算法，而采用确定性的
由粗到细搜索：

1. **粗扫**：在完整可行区间 $[30,v_{\max,i}]$ 内按 5 km/h 计算成本，找到粗网格上的全局最低点；
2. **加密**：在最低点左右各 5 km/h 内按 1 km/h 计算成本；
3. **精修**：在新的最低点左右各 1 km/h 内按 0.2 km/h 计算成本；
4. 每一阶段都保留非整步的道路速度上限，并缓存已经计算过的「路段 × 速度」，避免重复仿真。

如果粗扫存在多个局部低谷，第一层仍会覆盖整个区间并选择其中成本最低的候选，不会因为
第一次趋势反转就提前停止。

单段最多约评估：

$$
13+11+11=35
$$

个速度点；若直接按 0.2 km/h 穷举 30~90 km/h，则需要 301 个点。分层搜索用约十分之一的
计算量获得 0.2 km/h 的速度分辨率。物理模型输出另外保留未舍入的氢耗和电堆电量字段，
避免 0.2 km/h 级成本差异被四位小数舍入抹平。

## 五、氢电双补能动态规划

### 5.1 车辆能量参数

| 参数 | 取值 | 来源 |
| --- | --- | --- |
| 氢罐容量 | 50 kg | 49t 车型 35MPa 6×390L（56/50kg） |
| 动力电池容量 | 155 kWh | 海珀特官网 49t 车型参数 |
| SOC 可用窗口 | 10%~90% | 工程假设 |
| 快充功率 | 120 kW | 假设值（高德 POI 无功率） |
| 插枪/结算时间 | 0.15 h | 工程假设 |

### 5.2 DP 状态与动作

$$
\text{状态}=\left(i,\ h,\ SOC\right)
$$

其中 $i$ 为站点序号，$h$ 为已消耗氢量（离散档位），$SOC$ 为电池荷电状态（离散档位）。

每个站点的动作：

| 动作 | 说明 |
| --- | --- |
| 加氢 | 不加或加满（$h_{add}\in\{0,\ Q_{H_2}-h_{now}\}$） |
| 充电 | $e_{add}\in\{0,20,40,60,80,100\}$ kWh |
| 电池承担比例 | $\phi\in\{0,\ 0.5,\ 1\}$（该段行程由电池承担的比例，其余由氢承担） |

### 5.3 转移与成本

从站点 $i$ 前往后续可达站点 $j$（最多跳过 2 个站），该区间电耗需求为：

$$
E_{ij}=E(j)-E(i)
$$

电池可用能量与氢耗分别为：

$$
E_{bat}^{use}=\min\left(E_{ij}\cdot\phi,\ (SOC-SOC_{\min})\cdot Q_{bat}\right),\qquad
m_{H_2}^{use}=\frac{E_{ij}-E_{bat}^{use}}{\eta_{fc}\cdot LHV}
$$

转移成本：

$$
\Delta C=h_{add}\cdot p_{H_2}+e_{add}\cdot p_{elec}
+(c_d+\lambda)\left(t_{drive}+t_{charge}+t_{detour}\right)
$$

其中 $t_{charge}=e_{add}/P_{charge}+t_{plug}$，$t_{detour}$ 为绕行到站点的往返时间。

### 5.4 初始条件与约束

- 初始状态：满氢（$h=0$ 表示已消耗 0kg）、SOC=90%；
- 初始成本计入满氢与满电的价值：$Q_{H_2}\cdot p_{H_2}+(SOC_{\max}-SOC_{\min})\cdot Q_{bat}\cdot p_{elec}$；
- 约束：$0\le h\le Q_{H_2}$、$SOC_{\min}\le SOC\le SOC_{\max}$、到下一站前剩余能量非负。

### 5.5 离散化精度

| 维度 | 步长 | 说明 |
| --- | --- | --- |
| 剩余氢 | 0.25 kg | 过粗（如 5kg）会因取整把氢罐"算空"，导致决策失真 |
| SOC | 10% | 与电池容量 155kWh 对应约 15.5kWh/档 |

> 为保证能量守恒，氢量状态采用四舍五入（误差 ±0.125kg），SOC 采用向下取整（保守估计剩余电量）。

## 六、动态重规划

### 6.1 触发参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `replan-at` | 40% | 触发位置（占全程比例） |
| `replan-len` | 50 km | 受影响路段长度 |
| `replan-speed` | 0.7 | 限速系数（0.7 = 限速下降 30%） |
| `replan-consume` | 1.0 | 能耗系数（1.1 = 多耗 10%） |

### 6.2 重规划流程

```
① 定位触发点 s0 = 全程 × replan-at
② 取 s0 ~ s0+replan-len 的受影响路段
③ 车速上限 × replan-speed，能耗 × replan-consume
④ 重新扫描受影响路段的经济车速（物理模型）
⑤ 重算全程时长/氢耗，与基线比较
⑥ 输出偏差原因 + 下一段司机指令
```

### 6.3 输出示例

```
⚠️ 行驶至 124.3km 时检测到前方 50km 路况偏差：
   限速下降 40%、能耗×1.1，预计延误 25.2 分钟，超过阈值（10 分钟），触发滚动重规划

📢 司机指令：
   下一段 G50沪渝高速，保持 45 km/h；
   剩余 290.1km，调整后预计总时长 6.53h
```

## 七、实时监控

### 7.1 轮询机制

- 默认**每 5 分钟**（300 秒）轮询一次；演示模式可设为 30 秒；
- 使用 `noCache` 绕过高德路线 10 分钟缓存，保证拿到最新路况；
- 首次轮询建立"基线时长"，之后每次比较当前时长与基线的差值。

### 7.2 偏差判定与自动重规划

$$
\Delta T = T_{current}-T_{baseline}
$$

当 $\Delta T\ge 10$ 分钟时：

1. 记录"路况恶化"偏差事件；
2. **自动触发一次重规划任务**（后台异步执行）；
3. 前端事件日志实时展示（正常 / 偏差 / 重规划）。

### 7.3 前端展示

| 元素 | 内容 |
| --- | --- |
| 监控按钮 | 开启监控（5 分钟）/ 演示模式（30 秒）/ 停止 |
| 状态栏 | 监控状态、上次轮询时间、轮询间隔 |
| 对比栏 | 基线（里程/时长）vs 当前（里程/时长）、偏差阈值 |
| 事件表 | 时间 / 类型（ℹ️ 正常、⚠️ 偏差、🔁 重规划）/ 事件内容 |

## 十一、实测结果（武汉 → 恩施野三关）

| 指标 | 结果 |
| --- | --- |
| 总里程 | 414.5 km |
| 总时长 | 约 6.25 h |
| 氢耗 | 34.6 kg（约 8.35 kg/100km） |
| 电池用电 | 121.3 kWh |
| 广义总成本（λ=100） | 约 3427 元 |
| 补能次数 | 0 次（满氢 + 满电覆盖全程） |
| 能量校验 | 34.6×16.65 + 121.3 ≈ 697 kWh，与需求 692kWh 一致 |

**动态重规划实测**（30% 处、限速降 40%、能耗×1.1）：

- 触发位置 124.3 km，预计延误 25.2 分钟 → 超过阈值，触发重规划；
- 新指令：下一段 G50 沪渝高速，建议 45 km/h，剩余 290.1 km。

**实时监控实测**（30 秒演示模式）：

- 基线 414.7 km / 6.84 h → 当前 414.7 km / 6.85 h；
- 延误 0.6 分钟（阈值 10 分钟），记录"路况正常"事件。

| 速度外推 | 物理模型可靠，机器学习模型仅在真实车速区间训练；初始规划默认在 30 km/h 至道路重卡上限内搜索，并按 5 → 1 → 0.2 km/h 分层精修 |
| 离散化误差 | 氢量 0.25kg、SOC 10% 步长，存在小幅舍入误差 |
| 监控范围 | 当前监控高德路线级时长偏差；完整版需接入车辆 GPS/CAN 做"实际 vs 计划"比对 |
| 数据时效 | 充电价格/功率、加氢站可用性为假设或历史数据 |
| 防抖 | 生产版需加入"新方案优于当前 3% 以上才切换"的滞回逻辑 |

**后续计划**：

1. 接入车辆 GPS + CAN 实时状态，实现真正的"实际 vs 计划"偏差检测；
2. 更长路线（800km+）验证氢电双补能决策；
3. 加入滞回阈值与滚动时域（每 5 分钟只执行下一段）；
4. 充电站价格/功率数据接入（充电运营商 API 或用户输入）。
