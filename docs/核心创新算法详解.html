2路段自适应切分：把"一刀切"的路切成仿真爱吃的小块

2.1 痛点：高德按"转向动作"切段，仿真根本没法用

高德驾车路线是按"导航动作"切 step 的——高速上连续 90 公里不转弯，就只给 1 段；城区几米也给 1 段。若直接拿这些 step 做氢耗仿真：

  • 90km 长段里先爬升后下降，坡度被平均成 ≈0%，而重卡氢耗对坡度最敏感——爬坡要多烧、下坡能回收，全被抹平了；
  • 收费站 / 红绿灯 / 匝道这些"停车→启动"的行为区被吞进长段，起步的动能损耗被摊平，等于漏账。

文献实测：重卡用 5km 段平均速度预测能耗误差高达 25%，纳入坡度 / 载重 / 加速度后降到 11%（Transp. Res. Part D, 2025）。

2.2 方案：两层切分（L1 行为区标注 + L2 坡度自适应）

L1 行为区标注：按路网事件独立成段，并为每类事件给出变速情况与变速概率（概率事件按概率计入期望次数，与切分方式无关）。

事件变速情况变速概率（默认，可配置）
收费站（人工 / ETC）减速→(停车)→启动人工停车 P≈0.95；ETC 减速不停 P≈0.1
红绿灯路口减速→(停车)→启动停车是概率事件：单路口 P=0.35(畅通)~0.95(严重拥堵)，随实时路况变化
高速出入口匝道减速→并线→加速明显减速 P≈0.85
急转弯（指令 / 航向角>40°）减速→转弯→加速减速 P≈0.7

L2 坡度自适应切分：对所有 ≥1km 的段沿 DEM 剖面切分，三条判据：

\text{坡度变号必切：}\quad \operatorname{sign}(g_i) \ne \operatorname{sign}(g_{i+1}) \;\Rightarrow\; \text{切}
\text{坡度带阈值：}\quad \left|\,\overline{g}_{\,500m} - \overline{g}_{\,seg}\,\right| > 1.5\% \;\Rightarrow\; \text{切}
\text{长度约束：}\quad 0.5\;\mathrm{km} \le L_{sub} \le 10\;\mathrm{km}\qquad \text{短碎段不再一律合并}

目的：保证每个子段内部"坡度幅度小、行为单一"——要么整段上坡、要么整段下坡，不出现"一段里先上后下互相抵消"。这是物理仿真理想的输入单元。

图 2 · 90km 单段 → 行为区 + 坡度带切分（实测乌兰察布→天津：43 段 → 298 段）

把一条路想成一根香肠。高德是按"要不要转弯"来切的——高速上一直直走，就给你一整根 90 公里的大香肠。可是蒸香肠要熟透，得切小段：先在"收费站、红绿灯、匝道"这些必须停车的地方切一刀（行为区）；再摸一摸每一小段是上坡还是下坡，把"先上后下"混在一起的大段再切开（坡度带）。这样每一小段要么纯上坡、要么纯下坡，厨房（仿真模型）就能精准掌握火候——这一段要加多少力、那一段能回收多少，都不会被"平均"糊弄过去。

3工况合成（v-t 算法）：给新线路"演一遍"实车速度曲线

3.1 痛点：新线路只有"平均速度"，氢耗却对加减速极敏感

系统分段只提供每段的平均速度（比如 70 km/h）。但同样开 70，一路匀速巡航 vs 走走停停，氢耗能差 20%~50%。新线路没法实跑，只能靠实车数据"演"出最可能的速度曲线。

3.2 四步算法

① 建素材库：把两辆 H49 重卡 60s 实车数据按「道路等级 × 均速」分 8 个桶，每个桶里都是真实司机在这类路上的驾驶片段。

② 拼接：新线路某一段（比如"高速、80km/h"），就从对应桶里随机取速度片段，拼够这段的点数。

③ 均速对齐：把拼出来的曲线整体缩放到目标均速：

v'(t) \;=\; v(t)\cdot\frac{\bar v_{target}}{\bar v_{fragment}}

④ 坡度调制：重卡爬坡会掉速，按坡度微调：

v(t) \;\leftarrow\; v(t)\,\bigl(1 - 0.025\,g\bigr)\qquad (g\ \text{为坡度百分数，上坡为正})

最后加速度由差分得到 a = \tfrac{\Delta v}{\Delta t}，再从 v(t)/a(t) 里数出 9 个"驾驶体检指标"：

特征含义为什么重要
v_std速度波动标准差波动大 = 频繁加减速，同样均速更费氢
v_p8585 分位速度巡航实际跑多快
absa_mean / a_p90加速度均值 / 90 分位起步猛不猛
cruise_ratio / stop_ratio巡航占比 / 停车占比走走停停是城市段费氢主因
e_acc / e_aero / e_grade_up每公里加速 / 空阻 / 上坡能量三大能量项，直接决定氢耗
E_{acc} = \frac{1}{L}\sum_{t} \max(v\,a,\,0)\,\Delta t,\qquad E_{aero} = \frac{1}{L}\sum_{t} v^{3}\,\Delta t,\qquad E_{grade} = \frac{1}{L}\sum_{t} v\,g\,\sin\theta\,\Delta t
图 3 · 工况合成：8 桶素材库 → 拼接 → 对齐 → 坡度调制 → v(t)
👵 老奶奶版 · 演一遍

把实车司机在这类路上怎么踩油门的习惯，录成 8 个抽屉的素材库（高速抽屉、城市抽屉……）。新线路来了，就从对应抽屉里抽出几段"开车片段"拼起来，再拧到和目标速度一致、按坡度微调一下——就像给新线路请了个替身演员，照着剧本演一遍。演完再从戏里数出 9 个体检指标：速度稳不稳、巡航多快、刹车多猛、每公里花多少能量。这样模型就能分清"匀速省着开"和"走走停停费着开"——实测这套方法把段级 R² 从 0.31 提到 0.45+，是模型提升最大的环节。

4物理模型算法族：能量守恒公式引擎

不依赖任何训练数据，从车辆动力学与燃料电池原理按公式逐段算：四阻力 → 轮边功率 → 电堆/电池削峰 → 氢耗。每个中间量都可展开查看、可排序、可导出。

4.1 四阻力（L2）

F_{roll}=C_{rr}\,m\,g\cos\theta,\qquad F_{aero}=\tfrac12\rho(H)\,C_d A\,(v^2+\sigma^2),\qquad F_{grade}=m\,g\sin\theta,\qquad F_{acc}=\delta m\,a
\rho(H)=\rho_0\left(1-2.25577\times10^{-5}H\right)^{4.25588},\qquad F_{total}=F_{roll}+F_{aero}+F_{grade}+F_{acc}
  • 滚阻含 \cos\theta：陡坡时法向力略降，不虚高；
  • 空阻用 E[v^2]=\bar v^2+\sigma^2 修正：速度波动大 → 风阻大；
  • \rho(H) 随海拔修正空气密度（平原到高原差 10~15%）。

4.2 启停能耗（L2b，2026-08-23 新增）

匀速巡航假设在城市/收费站/路口会漏账：起步要把动能"买"进来，停车等待时附件与电堆最低功率还在烧氢。按段期望停车次数 N 计入：

E_{stop}^{ke}=N\cdot\tfrac12\,\delta\,m\,v^2\left(\tfrac1{\eta_{mt}}-\eta_{regen}\,\eta_{mt}\right),\qquad E_{stop}^{idle}=P_{fc}^{stop}\,N\,t_{stop}
P_{fc}^{stop}=\max\left(P_{fc}^{min},\,P_{aux}(T)\right),\qquad E_{fc}=P_{fc}\,t+E_{stop}^{ke}+E_{stop}^{idle}

单次停车时长按行为类型：收费站 60s / 服务区 40s / 红绿灯 30s / 匝道 20s / 转弯 10s；η_regen=0.30（低速城市启停回收低、机械制动为主）。N=0 时该项恒为 0，纯巡航模型不变（回归保证）。

4.3 动力总成（L3）与临界角

P_{drive}=\begin{cases}P_{wheel}/\eta_{mt}+P_{aux} & P_{wheel}\ge 0\ \text{（驱动）}\\ P_{wheel}\,\eta_{mt}+P_{aux} & P_{wheel}<0\ \text{（再生，链路损耗回收变少）}\end{cases}
\theta_c=\arctan(C_{rr})\approx 0.52^\circ\quad(\text{约 0.9\% 坡度})

临界角说明"下坡到底省不省"：缓下坡（\theta<\theta_c）仍需轻驱动；陡下坡（\theta>\theta_c）才真正"白捡"重力能，且要防超速、进入再生回收。代码不需要单独开关——由 P_{wheel}=F_{total}\,v 的符号天然判断。

4.4 电堆 / 电池削峰（SOC 平衡）

P_{fc}=\begin{cases}\min(P_{drive},P_{fc}^{max}) & P_{drive}\ge P_{fc}^{min}\\ P_{fc}^{min} & 0<P_{drive}<P_{fc}^{min}\\ P_{fc}^{min} & P_{drive}\le 0\ \text{（再生）}\end{cases},\qquad P_{bat}=\mathrm{clip}\left(P_{drive}-P_{fc},\,-P_{bat}^{max},\,P_{bat}^{max}\right)

电堆只在高效区（额定功率的 [10%,60%]）工作，低载/再生时保持最低稳定功率（避免关停-重启损耗），富余充电池；电池补差并受 ±限幅，超限部分由机械制动耗散。整个行程电池净放电约等于 0（削峰填谷），氢耗只看电堆。

物理模型就是给重卡算总账的：推着车跑，要克服四种"阻力"（轮胎磨地、撞开空气、爬坡、加速），这四笔账加起来就是轮子要出的力气（功率）。电机不能白出力，中间有损耗，还要养着空调气泵这些"附件"。电堆像锅炉、电池像蓄水池——锅炉只在最省火的档位烧，水多了先存起来、水少了再放出来。最后把烧掉的氢按热量一换算，就是这段路的氢耗。每一步都能给你看账本，不是黑箱。

5双引擎对比：数据驱动 × 机理模型互相印证

机器学习（HistGB，数据驱动）与物理模型（能量守恒，机理）共用同一套 \text{SegmentData} 输入契约：

机器学习引擎物理模型引擎
依据两辆 H49 实车数据（工况合成 + HistGB）车辆动力学 + 燃料电池原理（公式）
优点隐含实车的驾驶习惯与损耗不依赖数据、可解释、可手算验证
局限受数据缺陷影响（见 README 局限说明）依赖公式假设（η_fc、再生比例等）
用法双引擎同屏对比：结论一致 → 结果可信；差异大 → 提示检查输入或数据质量

6未来：物理 + 数据驱动融合模型（待研发）

目标：把物理公式换成"可学习的映射"，但隐藏层每个节点都是可解释的物理量（电堆功率 / 电机功率 / 电池功率 / 附件功率），而不是一堆没有含义的数字。

\underbrace{x}_{\text{天气/路况/载重}} \;\rightarrow\; \underbrace{h}_{\text{内部物理量（电堆/电机/电池/附件）}} \;\rightarrow\; \underbrace{y}_{\text{氢耗}}\qquad h=\phi(x),\;\; y=\psi(h)\ \text{（能量守恒约束）}

核心思想（文献锚点：Lei et al. 2025, Theory-Constrained NN, IEEE TVT）：物理保证可解释、数据保证精度——先用物理公式管住"输入→内部物理量→氢耗"的骨架，再用实车数据校准部件级偏差。
