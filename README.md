# 新线路氢耗预测工具（T05 · 命题二）

> 氢能车辆运营智能分析与决策助手 —— 面向市场销售人员的"新线路氢耗预测"Web 工具
> 赛题：浦发·IGNITE 未来能源黑客松 · T05（命题二：新线路氢耗预测工具）
> 命题企业：北京海珀特氢能科技有限公司

## 项目简介

输入**起点/终点地址** → 自动获取候选路线与逐段路况 → 逐段提取坡度/海拔/道路等级/沿线天气 → 用**机器学习 + 物理模型双引擎**预测每条路线的氢耗 → 给出费用构成、柴油对比、AI 推荐与可导出的对比报告，为"氢车跑这条新线路到底行不行、一公里几块钱"提供数据化决策依据。

```
起点/终点 → 候选路线(≤3条) → 路段自适应切分 → DEM高程/OSM等级/沿线天气 → 双引擎氢耗预测 → 费用/AI推荐/报告PDF
```

## ⚠️ 机器学习模型局限说明（重要，请先读）

本项目机器学习氢耗预测受**数据缺陷**限制，效果**并不理想**，请务必按以下口径理解与使用：

- **数据缺陷**：训练数据仅来自**两辆 H49 重卡**的 60s 聚合实车数据（含 GPS，仅本地使用，不入库）。两辆车覆盖的工况、载重、季节、司机风格有限，样本量小、代表性不足。
- **模型效果**：按行程分组交叉验证 R²≈0.38，误差与系统性偏差明显（企业原始 h2_remain 氢气剩余量毛刺占比 >99.9%，清洗后目标仍系统性低估；原始数据清洗与质量审计过程见仓库 `docs/data-quality-audit.md`，该报告已从应用内文档库移除，仅作历史过程留档）。**当前不能作为精准报价依据**。
- **定位**：本模型是**完整跑通「数据 → 特征工程 → 工况合成 → 训练 → 预测 → 前端」全链路的路径尝试（Proof of Concept）**——验证了"用实车数据驱动新线路氢耗预测"这一技术路线可行，同时真实暴露了数据质量与模型精度的瓶颈。
- **后续规划**：在获得更多高质量数据（更多车辆、可靠储氢计量、载重标签、秒级采集）后，将优化数据清洗与特征工程，并设计**更合理的机器学习算法**（按车型/场景分模型、时序模型、物理约束混合模型等），持续提升精度。

> 与之相对，**物理模型引擎不依赖训练数据**：从车辆动力学与燃料电池原理按公式逐段计算，可与机器学习互相印证——两者结论一致时结果可信，差异大时提示检查输入或数据质量。

## 实现原理简述

1. **路段自适应切分（核心创新）**：高德按"转向动作"切段，高速 90km 只给 1 段、坡度被平均成 0%。系统做两层切分——**L1 行为区标注**（收费站/红绿灯/匝道/转弯独立成段、带变速概率）+ **L2 坡度自适应切分**（坡度变号必切、坡度带阈值细分），保证每个子段"坡度幅度小、行为单一"，是仿真精度的关键。
2. **数据提取链路**：高德路线+实时路况 → DEM 高程（SRTM terrarium 瓦片，坡度/海拔/累计爬升下降）→ OpenStreetMap 真实路网匹配道路等级 → 和风天气按"出发时间+位置"逐段匹配温度/风/湿度/降水。
3. **机器学习引擎**：用两辆 H49 实车数据建**工况片段库**，把新线路"只有均速"还原成与实车统计一致的秒级速度曲线（工况合成），再算加速/空阻/上坡能量、速度分位数、启停占比等深度特征，用梯度提升树预测每段氢耗。
4. **物理引擎**：四阻力（滚动/空气/坡度/加速）→ 轮边功率 → 电堆/电池削峰 → 氢耗；含**启停能耗**（按期望停车次数计入动能净损耗 + 停车附件耗电）、再生回收与温度-附件耦合，输出 21 个中文名中间变量。
5. **决策与交付**：双引擎互相印证 → 费用构成（燃料/过路费/司机/其他）与柴油总费用对比 → AI 推荐路线 → 一键导出 PDF 对比报告。

## 附录：详细技术实现

### 创新点一：路段自适应切分 + 行为区标注（核心）

**痛点**：高德按"导航动作"切 step——高速连续 90km 只给 1 段、城区几米也给 1 段。若直接按 step 做氢耗仿真：① 90km 段坡度被平均（先爬升后下降 → ≈0%），而重卡氢耗对坡度最敏感；② 收费站/红绿灯/匝道等"停车-启动"行为区被吞进长段，启停能量被摊平。文献实测：重卡用 5km 段平均速度预测能耗误差高达 25%，纳入坡度/载重/加速度后降到 11%（Transp. Res. Part D, 2025）。

**方案 = 两层切分**（纯数据层，不依赖高德，可复现）：

**L1 行为区标注**——按路网事件独立成段，`motionBehavior` / `motionEvents` 字段：

| 事件 | 变速情况 | 变速概率（默认，可配置） |
| --- | --- | --- |
| 收费站（ETC/人工） | 减速→(停车)→启动 | 人工停车 P≈0.95；ETC 减速不停 P≈0.1 |
| 红绿灯路口 | 减速→(停车)→启动 | 停车是概率事件：单路口 P=0.35(畅通)~0.95(严重拥堵)，随实时路况变化 |
| 高速出入口匝道 | 减速→并线→加速 | 明显减速 P≈0.85 |
| 急转弯（指令/航向角>40°） | 减速→转弯→加速 | 减速 P≈0.7 |
| 服务区/城市起停 | 减速→(停车)→启动 | 按密度折算 |

**L2 坡度自适应切分**（对所有 ≥1km 段沿 DEM 剖面）：
1. **坡度变号必切**（山峰/山谷）→ 每子段只上坡或只下坡；
2. **坡度带阈值**：500m 滑动窗口平均坡度偏离当前段均值 > **±1.5%** → 切；
3. **长度约束** 0.5~10km；短碎段不再一律合并（仅"同路+无变速事件+<0.2km"纯延续碎段并入前段）。

**效果**（实测乌兰察布→天津 490km）：43 段 → **约 298 段**；京藏山区坡度逐段可辨（+5.44% / -5.86% / +6.22%）；收费站 2 座/匝道 5 处/转弯 10 处独立成段。

> 细节：① 事件只计"实际经过"的（长 step 尾部事件单独拆段、同一收费广场只计一次）；② **启停次数与切分方式无关**——段内路口数按「里程×路口密度」取期望值，同一条路怎么切，全线期望停车次数不变。

### 创新点二：OSM 真实路网道路等级

规则推断只能靠路名关键词猜等级。改用 OpenStreetMap 真实路网做**地图匹配**：Overpass 按路线走廊拉回 highway 线要素 → 路段折线点吸附到最近 OSM 路（≤150m + 航向平行，双向路接受反向数字化）→ 按 ref/name/way.id 聚合成"道路身份"投票，且必须覆盖本段 **≥30% 采样点** → 映射顺序 **motorway 物理证据 > 编号位数 > 城市路名后缀 > 标签兜底**（`S12` 机场高速不会被判成省道，`中山大道` 不会被升成国道）。Overpass 公共镜像限流时自动回退规则推断，面板顶部显示覆盖/兜底里程。

### 创新点三：地形分类对齐《公路路线设计规范》JTG D20

DEM 高程剖面按国标四档：平原（自然坡度≤3°）、微丘（3°~20°且相对高差<100m）、重丘（相对高差 100~200m）、山岭（相对高差>200m 或坡度>20°），评审可直接对标国标。

### 创新点四：按"出发时间 + 位置"逐段匹配沿线天气

温度不是整条路线一个值——重卡跑 6 小时出发地与目的地可能差 10℃。按每段到达时刻匹配**和风天气逐小时预报**（24h 窗口，超窗回退高德日预报）；0.05° 网格聚类 + 磁盘缓存控制调用量（490km 路线仅 6~10 次请求）；QWeather 用 GCJ-02 与高德零转换对齐；风速 <10.8km/h 视为无感风，物理模型不计风阻。

### 创新点五：实车数据驱动的段级氢耗预测（工况合成 + 梯度提升树）

系统分段只给"平均速度"，而氢耗对加减速/启停细节极敏感。用两辆 H49 实车 60s 数据建**工况片段库**（按道路等级×均速 8 桶），新线路每段从对应桶拼接 v/a 片段、按均速对齐、按坡度调制 → 算出加速/空阻/上坡能量、速度分位数、启停占比等深度特征 → HistGB 预测每段氢耗。真实目标用**氢气剩余量差分**（中位 ≈5.12 kg/100km，符合重卡实况），按行程分组 CV R²≈0.38。

> 👵 **通俗版**：把实车司机在这类路上怎么踩油门的习惯录成 8 个抽屉的素材库，给新线路"演一遍"速度曲线，再数出 9 个驾驶体检指标（速度稳不稳/巡航多快/刹车多猛/每公里能量），让模型能区分同样均速下匀速省着开 vs 走走停停费着开。

### 机器学习引擎（详细）

- **21 个特征来源**：`len_km`（GPS haversine / 高德里程）、`v_mean`（CAN 车速 / 高德均速）、`grade/elev/gain`（DEM）、`temp/wind/hum`（训练 ERA5 / 预测 QWeather）、`wind_par`（纵向风分量 w·cos(φ−θ)）、`hour`、`lv`（训练规则推断 / 预测 OSM）、9 个工况合成深度特征（v_std…e_grade_up）。
- **已知口径差异（如实披露）**：① 天气源不同（训练 ERA5 再分析 / 预测 QWeather 预报）；② 道路等级来源不同（regeo 推断 / OSM 匹配）；③ 里程口径不同（GPS haversine / 高德路线里程，影响约 1%）；④ 质量来源不同（训练行程级能量平衡反推 mass_kg，含 η/Crr/CdA 假设与官方锚点校准 / 预测用户输入载重+整备）。
- **训练评估**：按行程分组交叉验证 R²≈0.38（2026-08-23 重训）；加入质量特征 0.378→0.384；纵向风分量 0.382→0.385。详见技术原理页「机器学习」Tab。

### 物理模型引擎（详细）

- **公式链路**：四阻力 F_roll=Crr·m·g·cosθ / F_aero=½ρ(H)·Cd·A·(v²+σ²) / F_grade=m·g·sinθ / F_acc=δ·m·a → P_wheel=F·v → P_aux(T) 温度耦合 → P_drive（驱动 /η_mt、再生 ×η_mt）→ 电堆/电池削峰 P_fc/P_bat → E_fc=P_fc·t+E_stop → m_H₂=E_fc/(η_fc·LHV)。
- **启停能耗（2026-08-23 新增）**：按段期望停车次数 N 计入——动能净损耗 E_stop^ke=N·½δmv²·(1/η_mt−η_regen·η_mt)（η_regen=0.30，低速启停回收低）+ 停车附件/怠速 E_stop^idle=P_fc^stop·N·t_stop（P_fc^stop=max(P_fc^min,P_aux)）；N=0 时该项为 0，纯巡航模型不变。**物理约束（2026-08-24）**：有效停车速度按道路等级封顶（市区 30/县乡 35/国省道 50/快速 70/高速 80 km/h）、停车次数 ≤10 次/km、停车时长 ≤ 行驶时长、单段氢耗率上限 25 kg/100km——修复城区频繁停走导致氢耗虚高。
- **中间变量**：21 个中文名（车速/密度/四阻力/总力/轮边功率/附件/驱动/电堆/电池/时长/效率/电能/氢耗 + 启停 6 项），前端可排序、可导出 CSV。
- **手算验证**：设计文档附录 B 三路段工作簿（平路/上坡/下坡）→ 0.660/1.236/0.144 kg，合计 **2.040 kg、8.50 kg/100km**，与 `ml/physics.py` 逐段完全一致。
- **实测锚点**：乌兰察布→天津（~509.6km、39.7t）→ 物理模型 ≈7.3 kg/100km，落在官方满载锚点 7.1~8 范围内。
- **v1 简化（诚实披露）**：η_fc 固定 0.5、P_fc 三分支、电池 ±限幅、暂忽略动态 SOC 闭环；速度波动 σ 已用于 F_aero 修正。
